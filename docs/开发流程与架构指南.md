## 一、项目分层与开发原则

### 1.1 代码架构分层 (自底向上)

```
┌─────────────────────────────────────────────────────┐
│  Layer 5  应用层          main.cpp (CLI)            │
│                          RecorderEngine (编排)       │
├─────────────────────────────────────────────────────┤
│  Layer 4  协议抽象层      IProtocolSource / Sink    │
│                          ProtocolFactory            │
│                          LightFrame (统一数据帧)      │
├─────────────────────────────────────────────────────┤
│  Layer 3  底层实现        ArtNetReceiver / Sender    │
│                          QUdpSocket (NPU)           │
│                          QSerialPort (DMX512)       │
├─────────────────────────────────────────────────────┤
│  Layer 2  功能模块        ArtRecWriter / Reader     │
│                          FFmpegDecoder              │
│                          Logger                     │
├─────────────────────────────────────────────────────┤
│  Layer 1  基础设施        Common.h (常量/内联函数)    │
│                          CMakeLists.txt (构建)       │
└─────────────────────────────────────────────────────┘
```

### 1.2 依赖方向规则 (严格执行)

| 可以依赖 → | Layer 1 | Layer 2 | Layer 3 | Layer 4 | Layer 5 |
|-----------|---------|---------|---------|---------|---------|
| **Layer 1** | - | ✗ | ✗ | ✗ | ✗ |
| **Layer 2** | ✓ | - | ✗ | ✗ | ✗ |
| **Layer 3** | ✓ | ✓ | - | ✗ | ✗ |
| **Layer 4** | ✓ | ✗ | ✓ | - | ✗ |
| **Layer 5** | ✓ | ✓ | ✓ | ✓ | - |

**核心原则**: 上层依赖下层，同层可以不互相依赖，**下层绝对不能依赖上层**。违反此规则将导致循环依赖和测试无法独立运行。

### 1.3 开发三原则

1. **先写接口，再写实现** — 任何新模块先写 `.h` 纯虚接口，再写 `.cpp` 实现
2. **先写测试，再写功能** — TDD: 红 → 绿 → 重构
3. **保持模块边界清晰** — 每个文件/类职责单一，公共接口 = 稳定契约

## 二、分步开发流程 (每个新功能都按此执行)

### Step 1: 需求分析与接口设计

**输入**: 新功能描述 (如"添加 sACN 协议支持")

**产出**:
- 接口头文件 (如 `SacnSource.h` / `SacnSink.h`)
- 接口必须继承 `IProtocolSource` / `IProtocolSink`
- 只写 `.h`，**不写实现**

**检查点**:
- [ ] 接口是否只依赖 Layer 1-2 (不依赖上层)
- [ ] 所有虚函数签名和父类一致
- [ ] 是否需要新的 `ConnectionParams` 字段

### Step 2: 写单元测试 (TDD 红灯阶段)

**测试位置**: `tests/unit/` 下新建 `TestXxx.cpp`

**测试类型选择**:

| 测试对象 | 测试类型 | 依赖 |
|---------|---------|------|
| 纯函数/常量 (Common.h) | 直接测试 | 无 |
| 文件 I/O (ArtRecWriter) | 临时文件测试 | QFile |
| 网络协议 (ArtNetSource) | UDP 自环测试 | QUdpSocket |
| 串口协议 (Dmx512Source) | 条件跳过 | QSKIP 无硬件 |

**测试模板**:
```cpp
#include <QtTest>

class TestMyFeature : public QObject {
    Q_OBJECT

private slots:
    void test_case1() {
        // Given
        // When
        // Then (QCOMPARE / QVERIFY)
    }

    void test_case2_data() {
        QTest::addColumn<int>("input");
        QTest::addColumn<int>("expected");
        QTest::newRow("zero") << 0 << 0;
        QTest::newRow("basic") << 5 << 25;
    }
    void test_case2() { /* 驱动 data 表 */ }
};

QTEST_MAIN(TestMyFeature)
#include "TestMyFeature.moc"
```

**测试编写规则**:
- 测试名必须能**读成一句话**: `test_frameRateValue()` → "测试帧率值映射"
- 每个 test slot 只测一个行为
- 边界条件必须覆盖 (0, 最大值, 空输入, 损坏文件)
- 测试不应该互相依赖顺序

**添加到 CMakeLists.txt**:
```cmake
# tests/unit/CMakeLists.txt
add_unit_test(TestMyFeature
    EXTRA_SOURCES
        ${ARTNET_SRC_ROOT}/path/to/MyFeature.cpp
        # 依赖的其他 .cpp
)
```

### Step 3: 实现功能 (TDD 绿灯阶段)

- 让测试通过的**最简实现**
- 不做提前优化
- 代码注释解释"为什么"，不是"做什么"
- 对外部资源 (网络/串口/文件) 做好错误处理


**质量门禁**:
- [ ] 所有新增测试通过
- [ ] 所有旧测试仍然通过 (无回归)
- [ ] 无编译 warning (或已知的可接受 warning)

### Step 5: 集成测试

如果新功能涉及多个模块协作:
- 新建 `tests/integration/TestXxxPipeline.cpp`
- 测试从 Source → 引擎 → Sink 的完整链路
- 例如: UDP 发包 → Source 解析 → 引擎对齐 → Sink 收到

### Step 6: 文档更新

- 更新 `开发文档.md` 的架构图 / 模块清单
- 在本文档的扩展清单中勾选
- 命令行参数如有变化，更新 README

### 4.1 新增 Source 实现模板

```cpp
// protocol/sources/SacnSource.h
#pragma once
#include "protocol/IProtocolSource.h"

class QUdpSocket;

class SacnSource : public IProtocolSource {
    Q_OBJECT
public:
    explicit SacnSource(QObject *parent = nullptr);
    
    ProtocolType protocolType() const override { return ProtocolType::Sacn; }
    bool start(const ConnectionParams &params) override;
    void stop() override;
    bool isRunning() const override { return m_running; }
    void setFilterUniverses(const QList<quint16> &u) override { m_filter = u; }
    quint64 framesReceived() const override { return m_count; }

private slots:
    void onReadyRead();

private:
    QUdpSocket *m_socket = nullptr;
    bool m_running = false;
    QList<quint16> m_filter;
    quint64 m_count = 0;
    
    bool parsePacket(const QByteArray &data, LightFrame &out);
};
```

- 含 `Q_OBJECT` 的 `.cpp` 文件必须参与 AUTOMOC (被某个 target glob 到)

- **已解决**: `IProtocolSource.cpp` / `IProtocolSink.cpp` 就是空文件，触发 AUTOMOC 生成 moc

## 六、常见陷阱与解决方案

### 6.1 MOC 相关

| 问题 | 原因 | 解决 |
|------|------|------|
| undefined reference to `vtable for Xxx` | Q_OBJECT 类没有参与 AUTOMOC | 添加 `.cpp` 文件，或确保被 target 拾取 |
| signals/slots 宏失效 | CMakeLists 定义了 `QT_NO_KEYWORDS` | **删除** 这个 definition |
| moc 文件找不到 | `#include "Xxx.moc"` 的路径没配 | AUTOMOC 自动处理，检查 target 有没有 AUTOMOC |

### 6.2 GCC 8 兼容

| 问题 | 原因 | 解决 |
|------|------|------|
| `QCommandLineOption` 构造歧义 | 花括号初始化 `{"a", "b"}` 在 C++17 下歧义 | 改成 `QStringList() << "a" << "b"` |
| `quint8` 存不了 512 | UniverseEntry.channelCount | 约定 0 = 512，加 `realChannelCount()` |

### 6.3 Windows 特有

| 问题 | 原因 | 解决 |
|------|------|------|
| 测试 exe 一启动就退出无输出 | Qt DLL / MinGW DLL 不在 PATH | 复制 6 个 DLL 到测试目录 |
| Ctrl+C 无法优雅停止 | signal handler + QTimer 轮询 | 已用全局 atomic + QTimer |
| DMX512 BREAK 发送 | USB-DMX 设备差异 | `EscapeCommFunction(SETBREAK)` + fallback |

### 6.4 设计决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| IProtocolSource 继承 QObject | ✓ | 需要信号槽 `frameReceived` |
| IProtocolSink 继承 QObject | ✓ | 需要统一 UI 信号 `frameSent/sendError/statusChanged` |
| 测试直接链接 .cpp | ✓ | 避免 ODR 冲突，不另建静态库 |
| LightFrame 携带 universe + universeRaw | ✓ | ArtNet 编码 vs NPU 原始号 |
| .artrec 不用 CRC | 简化 | 录制工具，非传输协议 |

## 七、测试依赖层级

```
Layer 0: 纯函数 (无依赖)          ← 最先测试，必须全绿
  TestCommon (frameRate, Universe 编解码, TimeCode)

Layer 1: 文件 I/O (本地磁盘)      ← 必须全绿
  TestArtRecFormat (Writer → Reader round-trip)

Layer 2: 协议抽象层               ← 必须全绿
  TestProtocolFactory (工厂创建 + 生命周期)
  TestProtocolSources (ArtNet + Npu UDP 自环)
  TestProtocolSinks (ArtNet + Npu UDP 自环)

Layer 3: 集成测试                 ← 核心路径必须通过
  TestRecorderEngine (Source → 对齐 → Write → Sink)

Layer 4: E2E / 人工验证           ← 发布前验证
  真实 ArtNet 设备录制 → .artrec 文件
```

**扩展测试规则**:
- 新增协议 Source/Sink → 追加到 Layer 2，与现有测试并列
- 新增文件格式 → 追加到 Layer 1
- 新增时间码源 → 追加到 Layer 3 (需要端到端)
- GUI 相关 → 独立测试体系

### 10.1 ArtNet (v1.4 实现)

| 项目 | 值 |
|------|-----|
| 标准 | Art-Net v1.4 |
| 传输 | UDP/IP |
| 默认端口 | **6454** |
| 魔术字 | `"Art-Net\0"` (8 bytes) |
| Universe 空间 | Net(7bit) + SubNet(4bit) + Universe(4bit) = 16bit |

#### Universe 编解码

```cpp
// 编码
quint16 universe = (net & 0x7F) << 8 | (subNet & 0x0F) << 4 | (universe & 0x0F);

// 解码
quint8 net    = (universe >> 8) & 0x7F;
quint8 subNet = (universe >> 4) & 0x0F;
quint8 uni    = universe & 0x0F;
```

| **OP_DMX** | **0x5000** | **DMX 数据 (ArtDMX)** | **✅ Source/Sink 核心** |

| OP_INPUT | 0x5200 | 输入面板 | ✅ (接收忽略) |

#### ArtDMX 包格式 (OpCode=0x5000, 小端)

```
Offset  Size  Field            说明
──────  ────  ──────────────  ─────────────────────────
  0      8    ID               "Art-Net\0" 固定
  8      2    OpCode           0x00 0x50 (小端: 0x5000)
 10      2    ProtVer          0x0E 0x00 (小端: 14)
```

```cpp
QByteArray makeArtNetDmxPacket(quint16 universe, quint8 sequence, QByteArray dmx) {
    QByteArray p(530, 0);
    std::memcpy(p.data(), "Art-Net\0", 8);
    p[8] = 0x00; p[9] = 0x50;       // OpCode
    p[10] = 14;  p[11] = 0;          // ProtVer
    p[12] = sequence;
    p[14] = universe & 0xFF;         // Universe 小端
    p[15] = (universe >> 8) & 0xFF;
    p[16] = 512 & 0xFF;              // Length 小端
    p[17] = (512 >> 8) & 0xFF;
    std::memcpy(p.data()+18, dmx.constData(), dmx.size());
    return p;
}
```

### 10.3 DMX512 (串口)

| 项目 | 值 |
|------|-----|
| 标准 | ANSI E1.11 |
| 物理 | RS-485 差分 |
| 串口设置 | 250000 baud, 8N2 (或 8N1 + 2 stop) |
| 通道数 | 512 |
| 帧速率 | 最高 44 Hz (BREAK 间隔最短) |

#### 帧时序 (关键!)

```
                    BREAK        MAB      SC      DATA[0..511]
                 ├──────────┤ ├──────┤ ├──┤ ├──────────────────┤
                 │  ≥ 88μs  │ │≥8μs │ │1μs│ │   512 * 44μs      │
                 └──────────┘ └──────┘ └──┘ └──────────────────┘
                 ↓            ↓        ↓      ↓
              UART break    idle      0x00    每个字节: start + 8bit + 2stop = 44μs
```

| 阶段 | 时长 | 实现方式 |
|------|------|----------|
| **BREAK** | ≥ 88 μs (本项目用 `EscapeCommFunction(SETBREAK)` 1ms) | 硬件串口 break 信号 |
| **MAB** (Mark After Break) | ≥ 8 μs | `EscapeCommFunction(SENDIDLE)` 或 usleep |
| **SC** (Start Code) | 0x00 | 第一个字节 |
| **Channel Data** | 512 bytes × 44 μs | 连续写入 |

#### 本项目 DMX512 发送实现 (Dmx512Sender)

```cpp
bool Dmx512Sender::sendFrame(const QByteArray &dmx512) {
    // 1. BREAK
    EscapeCommFunction(m_handle, SETBREAK);
    QThread::usleep(1000);           // 1ms BREAK
    
    // 2. MAB
    EscapeCommFunction(m_handle, SENDIDLE);
    QThread::usleep(200);            // 200μs MAB
    
    // 3. SC (0x00) + 512 通道
    QByteArray frame;
    frame.append(char(0x00));        // SC
    frame.append(dmx512.leftJustified(512, 0));
    m_port.write(frame);
    
    return true;
}
```

#### Universe 映射约定

DMX512 是单 Universe 物理传输。多 Universe 输出的场景：
- **方案 A**: 多个 COM 口 (本项目支持, `Dmx512Sink` 每个实例一个端口)
- **方案 B**: USB-DMX 设备自带 universe 切换 (本项目可扩展)

### 10.4 sACN / E1.31 (规划中)

| 项目 | 值 |
|------|-----|
| 标准 | ANSI E1.31-2018 |
| 传输 | UDP/IP |
| 默认端口 | **5568** |
| 协议层 | ACN Root + DMX Universe |
| Universe 空间 | 1-63999 (16bit, 扁平编号) |

#### 包结构 (简化版)

```
ACN Root Layer
├─ Preamble Size      : 0x0010 (16)
├─ Postamble Size     : 0x0000 (0)
├─ ACN Packet Identifier: 0x41 0x53 0x43 0x2d 0x45 0x31 0x2e 0x31 (ASCII "ASC-E1.1")
├─ Flags & Length     : 0x72nn (Flags: 0x72 = V=1, P=1, O=0, U=0; Length = nn)
├─ Vector             : 0x00000004 (Root Layer Vector = E1.31 Universe Data)
└─ CID (Component ID) : 16 bytes

Framing Layer
├─ Flags & Length     : 0x72nn
├─ Vector             : 0x00000002 (Framing Layer Vector)
├─ Source Name        : 64 bytes UTF-8 (null-padded)
├─ Priority           : 1 byte (0-200, default 100)
├─ Synchronization Address: 2 bytes (小端)
├─ Sequence Number    : 1 byte (0-255)
├─ Options            : 1 byte (Bit 7: Terminated)
└─ Universe Address   : 2 bytes (小端, 1-63999)

DMP Layer (DMX Data)
├─ Flags & Length     : 0x72nn
├─ Vector             : 0x02 (DMP Set Property)
├─ Address Type & Data Type: 0xA1 (Address 1 byte, Data 1 byte)
├─ Starting Address   : 2 bytes (小端, 0x0000)
├─ Property Count     : 2 bytes (小端, 513 = SC + 512)
├─ DMX Data           : 1 byte SC (0x00) + 512 bytes Channel Data
└─ (可选) CRC         : 4 bytes CRC-32
```

**备注**: sACN 是分层设计 (Root → Framing → DMP)，每一层都有独立的 Length 字段。实现比 ArtNet 复杂得多。

### 10.6 .artrec 录制文件格式 (本项目自定义)

> **注意**: 此格式是本项目专属, 用于"录制 DMX 数据到本地文件"。
> 未来可能演进到 v2 (增加 Delta 压缩、索引等)。

#### 文件头 (ArtRecHeader, 固定 64 bytes, `#pragma pack(1)`)

```
Offset  Size  Field                说明
──────  ────  ───────────────────  ─────────────────────────
  0      8    Magic                "ARTREC\0\0" 固定
  8      2    Version              小端 0x0100 (v1.0)
 10      2    Frame Rate           quint16, 如 30, 25, 24, 29, 60
 12      1    TimeCode Type       0=None, 1=MTC, 2=Video, 3=LTC
 13      1    TimeCode Format      0=24, 1=25, 2=29.97, 3=30
 14      1    Reserved             0x00
 15      1    Universe Count       本文件录制的 Universe 数
 16      8    Total Frames         录制总帧数 (quint64 LE)
 24      8    Total Duration Us    录制总时长 (微秒, quint64 LE)
 32      8    Create Timestamp     Unix 时间戳 (微秒, quint64 LE)
 40      8    Media File Offset    媒体文件名字在文件中的偏移 (0=无)
 48      8    Media File Length    媒体文件名长度 (0=无)
 56      8    Reserved             0...0
────────────────────────────────────────────────────────
总计: 64 bytes
```

#### Universe 映射表 (紧接 Header, 每项 4 bytes)

```
每项 4 bytes:
  [0] net           : quint8 (0-127)
  [1] subNet        : quint8 (0-15)
  [2] universe      : quint8 (0-15)
  [3] channelCount  : quint8 (0 = 512, 否则 = 实际值)

总计: Universe Count × 4 bytes
```

#### 帧数据区 (变长, 循环)

每个帧由 **FrameRecordHeader** + N 个 **UniverseDataBlock** 组成：

```
FrameRecordHeader (15 bytes, #pragma pack(1)):
  Offset  Size  Field            说明
  ──────  ────  ──────────────  ─────────────────────────
    0      8    Frame Index      quint64 LE, 从 0 开始
    8      6    Timestamp Us     quint48 LE (微秒)  ← 非标准, 实际用 quint64
   14      1    Flags            bit 0: end-of-file marker

UniverseDataBlock (每项 4 + 512 bytes):
  Offset  Size  Field            说明
  ──────  ────  ──────────────  ─────────────────────────
    0      2    Universe Index   quint16 LE (指向映射表的索引)
    2      2    Data Length     quint16 LE (通常 512)
    4    512    DMX Data        DMX 通道值

总计 per frame: 15 + UniverseCount × (4 + 512) bytes
```

#### 文件尾 (可选)

```
若 header.MediaFileOffset > 0:
  从 MediaFileOffset 开始: MediaFileLength bytes 的媒体文件名字符串 (UTF-8)
```

#### 完整示意

```
Byte 0  ──┐
          │ ArtRecHeader (64 bytes)
Byte 64 ──┘
          ────────────────────────
Byte 64 ──┐
          │ UniverseEntry[0] (4 bytes)
          │ UniverseEntry[1] (4 bytes)
          │ ...
Byte 64+N×4 ──┘
          ────────────────────────
Byte 64+N×4 ──┐
              │ FrameRecordHeader (15 bytes)
              │ UniverseDataBlock[0] (4+512 bytes)
              │ UniverseDataBlock[1] (4+512 bytes)
              │ ...
              │ FrameRecordHeader (15 bytes)
              │ UniverseDataBlock...
              │ ...
              │ FrameRecordHeader (15 bytes, Flags bit0=1) ← 最后一帧
              │ UniverseDataBlock...
Byte EOF    ──┘
          ────────────────────────
(可选) Media filename
```
