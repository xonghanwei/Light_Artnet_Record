# Light_Artnet_Record 测试驱动开发计划

> 本文档既是测试计划，也是**架构验证清单**——写测试的过程就是验证接口设计的过程。

---

## 1. 原则

1. **每个模块 = 一个测试目标**, 模块边界 = 测试边界
2. **先测无外部依赖的纯逻辑**, 再测需要网络/串口/硬件的模块
3. **测试只包含公开头文件**, 不 include 私有 .cpp
4. **断言只对明确契约**, 不对隐式实现细节
5. **Mock 必须先读接口头文件再写**, 不能猜 API

---

## 2. 依赖层级 & 测试类型

按依赖关系划分测试顺序:

```
Layer 0: 纯值/纯计算 (无外部依赖) ──── 单元测试 (必须通过)
  Common.h, TimeCode, 帧编码/解码, ProtocolFactory 名称映射

Layer 1: 文件 I/O (本地磁盘) ──────── 单元测试 (必须通过)
  ArtRecWriter / ArtRecReader 读写 .artrec 文件

Layer 2: 协议抽象层 (依赖 Layer 0) ─── 单元测试 + Mock (必须通过)
  IProtocolSource / IProtocolSink 接口契约
  LightFrame 转换正确性
  ArtNetSource / ArtNetSink (UDP 环回测试)
  NpuSource / NpuSink
  Dmx512Source / Dmx512Sink (无硬件时跳过)

Layer 3: 网络收发 (依赖 Layer 2) ───── 集成测试 (可选)
  ArtNetReceiver / ArtNetSender 真实 UDP 收发
  需要两台进程或自环

Layer 4: 媒体解码 (依赖 FFmpeg) ───── 集成测试 (可选)
  FFmpegDecoder 真实视频解码
  需要测试视频文件

Layer 5: 录制引擎 (依赖 Layer 1-3) ── 集成测试 (核心路径必须通过)
  RecorderEngine 端到端: Source → 对齐 → Write → Sink

Layer 6: 命令行 (依赖全部) ────────── E2E 测试 (人工验证)
  main.cpp 参数解析 + 实际录制
```

```cmake
# tests/unit/CMakeLists.txt

# 每个 test 一个可执行文件, 自动 Qt Test 注册
function(add_artnet_test name)
    add_executable(${name} ${name}.cpp)
    target_link_libraries(${name} PRIVATE
        Qt5::Test
        Qt5::Core
        Qt5::Network
        Qt5::SerialPort
    )
    target_include_directories(${name} PRIVATE
        ${CMAKE_SOURCE_DIR}/src
    )
```

## 4. 分阶段测试计划

### Phase 1: Core 层 (无外部依赖) — 预计 3 个测试目标

#### TestCommon
| 测试项 | 方法 | 断言 |
|--------|------|------|
| `frameRateValue()` 整数映射 | FPS_24/25/FPS_2997/FPS_30/FPS_60 | 返回 24/25/29/30/60 |
| `frameRateDouble()` 精确值 | FPS_2997 | 返回 29.97 (近似 0.01) |
| `frameIntervalUs()` 每帧微秒数 | FPS_30 | 返回 33333 |
| Universe 编码 | encodeUniverse(0,0,0) | 0x0000 |
| Universe 解码 | universeNet/SubNet/Number | 编解码 round-trip 相等 |
| TimeCode `toTotalFrames()` | 01:00:00:00 @ 30fps | 108000 |
| TimeCode 丢帧 29.97 | toTotalFrames / fromTotalFrames | round-trip |
| ArtNet 魔术字 | `memcmp(ArtNet::ID_STRING)` | 等于 "Art-Net\0" |

#### TestProtocolFactory
| 测试项 | 方法 | 断言 |
|--------|------|------|
| `nameToType("artnet")` | → ProtocolType::ArtNet | |
| `nameToType("NPU")` | → ProtocolType::Npu | 大小写不敏感 |
| `nameToType("DMX512")` | → ProtocolType::Dmx512 | |
| `nameToType("unknown")` | → ProtocolType::Unknown | |
| `createSource("artnet")` | 返回非空 IProtocolSource* | protocolType == ArtNet |
| `createSource("")` | 返回 nullptr | |
| `createSink("npu")` | 返回非空 IProtocolSink* | protocolType == Npu |
| `supportedProtocols()` | 返回 3 个以上 | |

### Phase 2: File Format 层 (磁盘 I/O) — 预计 1 个测试目标

#### TestArtRecFormat
| 测试项 | 方法 | 断言 |
|--------|------|------|
| Writer 创建文件 | create(tempFile, header, entries) | 文件存在, 大小 = 64 + N×4 |
| Writer 写入 0 帧后 close | finalize(0, 0) | header.totalFrames == 0 |
| Writer/Reader round-trip | 写 5 帧 → 读 → 比较 | 帧数、时间戳、DMX 数据完全一致 |
| 文件头 Magic 验证 | 读 .artrec 文件 | header.isValid() == true |
| 损坏文件处理 | 读 .txt 文件 (非 artrec) | open() == false |
| 多 Universe 写入 | 3 个 universe, 10 帧 | 读回来每个 universe 正确 |
| DMX 数据变化检测 | 连续帧变化 | flags & FLAG_DATA_CHANGED |
| ArtRecHeader packed 大小 | sizeof(ArtRecHeader) | == 64 (#pragma pack 生效) |
| UniverseEntry packed 大小 | sizeof(UniverseEntry) | == 4 |
| 帧序号递增 | 连续写 frameIndex 0,1,2 | 读回来顺序 0,1,2 |

---

### Phase 3: Protocol Sources 层 (UDP 可自环测试) — 预计 1 个测试目标

#### TestProtocolSources
| 测试项 | 方法 | 断言 |
|--------|------|------|
| ArtNetSource start/stop | 监听 6454 | isRunning() == true → false |
| ArtNetSource DMX 解析 | 手工构造 ArtDMX 包 → 发送到 6454 | LightFrame.dmxData == 512 bytes |
| ArtNetSource Universe 过滤 | filterUniverses={1}, 发送 universe 0 包 | frameReceived 不触发 |
| ArtNetSource Universe 过滤 | filterUniverses={1}, 发送 universe 1 包 | frameReceived 触发, lf.universeRaw == 1 |
| NpuSource start/stop | 监听 9999 | isRunning() |
| NpuSource DMX 解析 | 手工构造 Npu DMX 包 → 9999 | lf.universeRaw == 原始号 |
| NpuSource 长度校验 | 发送错误长度的包 | 不 crash, 静默丢弃 |

**Mock 方式**: 在测试里开一个 UDP socket 当作 sender, 发真实 ArtNet/NPU 包给被测试 Source 的端口。这不是 Mock, 是**真实协议环回**。

---

### Phase 4: Protocol Sinks 层 (UDP/串口) — 预计 1 个测试目标

#### TestProtocolSinks
| 测试项 | 方法 | 断言 |
|--------|------|------|
| ArtNetSink sendFrame | 构造 LightFrame → sendFrame | Sink 内部 DMX 数据被消费 |
| ArtNetSink 多目标 fan-out | addTarget("127.0.0.1", port1), addTarget("127.0.0.1", port2) | 两个 listener 都收到 DMX |
| NpuSink sendFrame | LightFrame → 组 NPU 包 | 接收端解析出 cmd=0x01, universe=lf.universeRaw |
| Dmx512Sink (跳过无硬件) | #if 保护 | QSKIP("需要 DMX512 硬件") |

---

### Phase 5: RecorderEngine (集成测试) — 预计 1 个测试目标

#### TestRecorderEngine (集成测试)
| 测试项 | 方法 | 断言 |
|--------|------|------|
| 内部时钟录制基本流程 | start → sleep 1s → stop | 文件存在, totalFrames >= 24 (25fps) |
| 录制文件验证 | 用 ArtRecReader 读回 | frames, timestamps, DMX 匹配 |
| 录制 + 转发 | 录制同时配 Sink 目标 | Sink 收到 DMX 数据 |
| Ctrl+C 优雅停止 | 启动后台线程, 触发中断信号 | finalize 被调用, 文件可打开 |
| 最大时长自动停止 | maxDurationUs=2s | 2s 后自动 stop |
| Universe 过滤 | 配置 universe={0,1}, Source 发 universe=2 的包 | 不录制 universe=2 |

## 5. 需要特殊处理的模块

### 5.1 需要 Mock 的模块

| 模块 | 为什么需要 Mock | Mock 策略 |
|------|----------------|-----------|
| **FFmpegDecoder** | 需要 FFmpeg 库 + 真实视频文件 | 编译开关 NO_FFMPEG 时跳过相关测试 |
| **Dmx512Sender / Dmx512Source** | 需要物理串口 + USB-DMX 硬件 | 条件跳过: `QSKIP("需要 DMX512 硬件")` |
| **ArtNetReceiver** | 可以用真实 UDP 自环, 不需要 Mock | 测试里直接 QUdpSocket 发包 |

### 5.2 不需要 Mock 的模块 (纯逻辑)

| 模块 | 为什么不需要 Mock |
|------|------------------|
| **Common.h** | 纯常量 + 函数, 零依赖 |
| **TimeCode** | 纯计算 |
| **ArtRecWriter/Reader** | 只用 QFile, 临时文件可任意创建 |
| **ProtocolFactory** | 纯 switch-case, 工厂本身不做 I/O |

## 6. 分阶段开发顺序

> 每阶段只做该阶段的代码 + 该阶段的测试 + 验证测试全绿 → 再进入下一阶段。

```
Phase 1 (1-2天) ──→ Core 层 + 2 个单元测试全绿
│                    ↓
Phase 2 (1-2天) ──→ FileFormat 层 + 1 个 round-trip 测试全绿
│                    ↓
Phase 3 (2-3天) ──→ Protocol Sources 层 + 真实 UDP 环回测试全绿
│                    ↓
Phase 4 (2-3天) ──→ Protocol Sinks 层 + fan-out 测试全绿
│                    ↓
Phase 5 (2-3天) ──→ RecorderEngine 集成测试 + E2E 验证
│                    ↓
Phase 6         ──→ 修复测试暴露的 Bug, 回归验证
```

## 9. 当前代码 vs 未来模块 (为扩展预留)

| 未来模块 | 测试时需要什么 | 当前是否可测试 |
|---------|--------------|---------------|
| sACN (E1.31) Source/Sink | 继承 IProtocolSource/IProtocolSink 接口 | 接口已就绪 |
| QML/Qt Widgets GUI | UI 测试需要 QTest 或 Squish | 暂无 |
| MIDI 时间码 (MTC) | 需要 MIDI 库 + 输入设备 | 暂无依赖 |
| LTC 音频时间码 | 需要音频文件 + 解码库 | 暂无依赖 |

**核心原则**: 未来所有 Source/Sink 实现必须继承 IProtocolSource/IProtocolSink, 这样 Phase 3/4 的现有测试框架直接能跑, 只需追加新的 test case。

## 10. 立即可执行的 Phase 1 内容

Phase 1 代码**不需要任何外部硬件/库**就能跑。建议顺序:

1. 写 `tests/unit/TestCommon.cpp` —— 测 Common.h 里的所有纯函数
2. 写 `tests/unit/TestProtocolFactory.cpp` —— 测工厂创建 + 名称映射
3. 写 `tests/CMakeLists.txt` + 顶层 `tests/CMakeLists.txt`
4. 配置 CMake `-DBUILD_TESTING=ON`, 编译 + `ctest`
5. **修复任何测试暴露的 Bug, 直到全绿**

Phase 1 全绿 → 项目基础稳固, 后续所有扩展都在这个地基之上。
